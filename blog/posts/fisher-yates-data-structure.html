Fisher-Yates data structure

My favourite random numbers bag data structure

November 19, 2025 (16 days ago) @boborgo

The problem: generating unique random numbers

I recently found myself in a situation where I needed to generate five random numbers, and I absolutely didn't want any of them to be repeated. The naive approach would be to keep generating random numbers and checking if they've been used before, but that's inefficient and can lead to unpredictable performance—especially as the pool of available numbers shrinks.

I started looking for an efficient way to solve this problem. The key insight I was searching for was a data structure that could maintain a pool of available numbers and allow me to randomly extract from it, ensuring uniqueness without any duplicate checking overhead.

During my research, I encountered the The Fisher-Yates shuffle algorithm. This algorithm provided exactly what I needed: a way to randomly select unique values from a range. I realized I could adapt it to create a "bag" data structure where numbers are randomly drawn and removed, guaranteeing uniqueness. This led me to implement a C# library called fisher-yates-dotnet that uses the Fisher-Yates algorithm as the foundation for this efficient random numbers bag.

What is the Fisher-Yates shuffle?

The Fisher-Yates shuffle is an algorithm for generating a random permutation of a finite sequence. It ensures that every possible permutation is equally likely, which makes it perfect for unbiased random selection. The modern version of the algorithm, introduced by Richard Durstenfeld in 1964, operates in O(n) time complexity and shuffles the sequence in place.

The classic algorithm works by iterating through the array from the last element to the first. For each position, it picks a random index between zero and the current position (inclusive), then swaps the element at that random index with the element at the current position. This guarantees that each element has an equal chance of ending up in any position.

However, my implementation takes a different approach: instead of shuffling the entire array upfront, it applies the Fisher-Yates principle incrementally. The array starts in order, and each time you extract a value, it performs one swap operation—effectively doing one step of the Fisher-Yates shuffle on demand. This means you only pay the cost of shuffling for the values you actually extract.

How the algorithm works visually

Let me walk you through how the incremental Fisher-Yates approach works. The array starts in order, and shuffling happens on demand with each extraction:

  • RemainingCount is initialized to the range size.
  • LastIndex is initialized to the last index of the array.
  • We start with an array containing all possible values in order. In this example, we have numbers from 0 to 9. The array is not shuffled yet—it's initialized in sequential order.
  • When we call GetNextRandom(), we pick a random index from the Active portion (0 to LastIndex—excluded). Let's say we pick index 4.
  • We swap the value at index 4 with the value at the last active position, then decrement the LastIndex—this single swap operation is O(1).
  • We can now return the value that we have moved into the "already extracted" tail.
  • For the next extraction, we again pick a random index from the remaining active portion...
  • ... swap it with the last active position, decrement the LastIndex and return the value that we have moved into the "already extracted" tail.

My implementation: a random numbers bag

I wrapped the Fisher-Yates algorithm in a simple class that acts like a bag of numbers. You initialize it with a range (min and max), and it creates an internal array with all values in that range, initialized in order. The key difference from a traditional Fisher-Yates shuffle is that the array is not shuffled upfront—instead, shuffling happens incrementally each time you extract a value.

Here's a simple example of how to use it:

using FisherYates;

var bag = new FisherYatesBag(13, 27);
var number = bag.GetNextRandom();
Console.WriteLine(number); // e.g., "19"

The beauty of this implementation is that if you only need a few random numbers (like 3 out of 100), you get them in O(3) = O(1) time per extraction, not O(100).
The algorithm is based on Fisher-Yates but optimized for partial extractions.

Why I love this data structure

What makes this approach elegant is that it doesn't generate random numbers at all, and it doesn't shuffle the entire array upfront. Instead, it maintains an array of all possible values in order, and applies the Fisher-Yates principle incrementally: each time you extract a value, it performs one swap operation to randomize the selection.

This means:

  • No duplicate checking needed: Once a value is extracted, it's physically removed from the available pool by swapping it to the "used" portion of the array
  • O(1) extraction time: Each GetNextRandom() call takes constant time—just one random index selection and one swap operation
  • O(k) for k extractions: If you need k random numbers, ExtractKRandomNumbers(k) takes O(k) time, not O(n)
  • True randomness: The incremental Fisher-Yates approach guarantees uniform distribution, just like the classic algorithm
  • No wasted work: If you only need 3 numbers from a range of 1000, you only perform 3 swap operations, not 1000
  • No wasted random number generations: You're not generating random numbers that might be duplicates and need to be discarded

The randomness comes from the incremental shuffling on each extraction, not from generating random numbers or shuffling everything upfront. This makes it perfect for scenarios where you need a small subset of unique random numbers from a larger range.

Limitations and solutions

Like any data structure, this one has its limitations. The most obvious one is memory: since we need to store an array with all possible values in the range, very large ranges can consume significant memory.

For example, if you try to create a bag for numbers from 0 to 1,000,000, you'll need an array of one million integers. That's about 4 MB of memory, which might be acceptable depending on your use case, but if you're working with ranges in the billions, you'll run into memory issues.

For such cases, you'd need a different approach. One solution could be to use a hash set to track used numbers and generate random numbers on the fly, accepting the potential for collisions and retries. Another approach might be to use a mathematical formula to generate unique random numbers without storing all possibilities, though this can be more complex and might have limitations depending on your specific requirements.

For most practical purposes, though, the range-based bag works perfectly. If you're generating random numbers in a typical range (say, 0 to 10,000), the memory footprint is negligible.

Thread safety

It's important to note that my current implementation is not thread-safe. If multiple threads try to extract numbers from the same bag instance simultaneously, you'll get unpredictable behavior and potential data corruption.

If you need thread-safe access, you have a few options:

  • Use a lock or mutex to synchronize access to the bag
  • Create separate bag instances for each thread
  • Implement thread-safe operations using atomic operations or concurrent collections

For single-threaded scenarios, which cover most use cases, the current implementation is perfectly fine.

Use cases

This random numbers bag data structure is useful in several scenarios:

Password generation

You can use multiple bags to generate passwords with specific constraints. For example, a 12-character password with 2-4 special characters and 2-3 capital letters:

using FisherYates;
/*
* The password length is 18 characters.
* The special characters are !@#$%^&*()-_=+[]{}<>?/.
* The upper case letters are ABCDEFGHIJKLMNOPQRSTUVWXYZ.
* The lower case letters are abcdefghijklmnopqrstuvwxyz.
* The digits are 0123456789.
* The password must contain 2-4 special characters, 2-3 upper case letters, and 1-3 digits.
*/
const int passwordLength = 18;
const string specialChars = "!@#$%^&*()-_=+[]{}<>?/";
const string upperChars = "ABCDEFGHIJKLMNOPQRSTUVWXYZ";
const string lowerChars = "abcdefghijklmnopqrstuvwxyz";
char?[] password = new char?[passwordLength];

int numOfSpecials = Random.Shared.Next(2, 5);
FisherYatesBag specialCharsBag = new(0, specialChars.Length - 1);
IEnumerable rndSpecialCharsIdxs = specialCharsBag.ExtractKRandomNumbers(numOfSpecials);

int numOfUpperCaseLetters = Random.Shared.Next(2, 4);
FisherYatesBag upperCaseLettersBag = new(0, upperChars.Length - 1);
IEnumerable rndUpperCaseLettersIdxs = upperCaseLettersBag.ExtractKRandomNumbers(numOfUpperCaseLetters);

int numOfDigits = Random.Shared.Next(1, 4);
FisherYatesBag digitsBag = new(0, 9);
IEnumerable rndDigits = digitsBag.ExtractKRandomNumbers(numOfDigits);

FisherYatesBag positionsBag = new(0, passwordLength - 1);
foreach (int idx in rndSpecialCharsIdxs) {
    int pos = positionsBag.GetNextRandom();
    password[pos] = specialChars[idx];
}
foreach (int idx in rndUpperCaseLettersIdxs) {
    int pos = positionsBag.GetNextRandom();
    password[pos] = upperChars[idx];
}
foreach (int digit in rndDigits) {
    int pos = positionsBag.GetNextRandom();
    password[pos] = (char)('0' + digit);
}

StringBuilder sb = new();
FisherYatesBag lowerCaseLettersBag = new(0, lowerChars.Length - 1);
foreach (char? c in password) {
    if (c is not null) {
        sb.Append(c);
        continue;
    }
    int lowerCaseIdx = lowerCaseLettersBag.GetNextRandom();
    sb.Append(lowerChars[lowerCaseIdx]);           
    
}

return sb.ToString(); // e.g., "zqwrAM?Bfc!95gpd2h"

Randomized testing

When running test suites, you might want to execute tests in a random order to catch dependencies between tests. The bag ensures each test runs exactly once, but in a random sequence.

Game development

In games, you might need to randomly select items, events, or positions without repetition. For example, randomly placing power-ups on a map, or selecting random quests from a pool.

Sampling without replacement

In data science or statistics, you might need to sample a subset of data points without replacement. The bag provides an efficient way to do this for integer-based sampling.

Shuffling playlists

If you're building a music player, you could use this to create a truly random shuffle of a playlist, ensuring each song plays exactly once before repeating.

Conclusion

The Fisher-Yates shuffle is a beautiful algorithm, and my implementation takes it one step further by applying it incrementally. By maintaining an array of possible values and shuffling only what you need on each extraction, we get random extraction in O(1) time per value without the overhead of generating random numbers and checking for duplicates.

This solves various scenarios efficiently: generating 3 random numbers without collisions takes O(3)~O(1) time, not O(n).

It's not perfect for every scenario—very large ranges will consume too much memory, and it's not thread-safe out of the box—but for most practical purposes, especially when you need a small subset of unique random numbers from a larger range, it's an elegant and efficient solution.

High school knowledge (15 years later)

Finally occured to apply some knowledge from my 'Probability and Statistics' course from high school

December 4, 2025 (1 day ago) @boborgo
What am I studying math for? I will never use it in my life.

I swear, when I was younger - especially during high school - I used to hear some friends say these words during our free time after school: "What's the purpose of knowing why or how to solve an integral? I will never ask the greengrocer to give me 'integral from 0 to infinity of x^2 dx' apples!"

I've always laughed at those jokes, but deep inside I was wondering if there was something to them.
Is a person who has no interest in obtaining a future (job) in a theoretical field really supposed to study maths (or similar subjects)?

Well, since this argument isn't the main focus of this post, I will answer briefly: Yes.

Here is my story of how a concept from high school 'Probability and Statistics' course finally occurred to help me out (15 years after learning it).

Fisher-Yates data structure unit tests

When I was writing the C# code for the 'Fisher-Yates data structure' (article here) I was unsure about how well I had applied the algorithm in my data structure. So during my TDD approach I was looking for a way to test whether the randomness of the algorithm was good enough. It was in that moment that some knowledge from high school finally occurred to me: the Chi-square test.

Chi square (χ2) test

Pearson's chi-squared test is used to determine whether there is a statistically significant difference between the expected frequencies and the observed frequencies in one or more categories of a contingency table.
(Wikipedia)

Once some constraints are met (for the sake of simplicity we summarize it like that), the test can be used to determine whether a hypothesis (h0) should be rejected or not (we usually say that we “fail to reject” it).

Let's model the test for a simple case: we want to know if my FisherYatesBag, after many extractions, really gives each value the same probability of being extracted.

Here's how to proceed:

  • Identify your h0. In this case it is the hypothesis that each number has the same probability of being extracted from the FisherYatesBag.
  • h1 is the negation of h0: not all numbers have the same probability of being extracted from the FisherYatesBag.
  • Assign a significance level (α) to the test. This is the probability of rejecting the h0 hypothesis when it is actually true. ( We want it small, like 1% = 0.01)
  • Calculate the df (degrees of freedom) of the test. df = n - 1, where n is the number of categories. (e.g.: with a FisherYatesBag of size 10, df = 9)
  • Call CV (critical value) the threshold value that separates the region where we reject the hypothesis (h0) from the region where we do not reject it.
Now you just need to calculate the value of χ2 and compare it with CV: if χ2 is greater than CV, we reject h0 and accept h1; otherwise we do not reject h0.
  • Knowing α and df; CV can be found in the Chi-square distribution table.
  • χ2 = ∑ [ ( Oi - Ei )2 / Ei ]
    with:
    • Oi: Observed frequency
    • Ei: Expected frequency

Chi square (χ2) test (on many random permutations)

Let's take a step forward and apply the test to many random permutations of the FisherYatesBag.

The idea is to state the h0 hypothesis as "Each value in the range of the FisherYatesBag has the same probability of appearing in each position".

Paraphrasing, we want to know if 0 has the same probability of being extracted as first, second... last number. The same for other values 1,2,...max in the range.
A developer can see how our categories can be defined here: through a matrix that tells us how many times each value occurred in each position.

Assuming each value has the same probability of being extracted in each position, we can identify the expected frequency (same for each category) as
num_of_trials / num_of_categories_per_trial.

Last but not least, we need to calculate the df that for a matrix is
df = (num_of_rows - 1) * (num_of_columns - 1).

And that's it:

public void FisherYatesBag_Distribution_IsUniform_ChiSquare()
{
    // h0: each value (0,1,2,..) appear in each position (0,1,2,..) with the same probability
    // h1 = NOT(h0)
    const int fisherYatesRangeMax = 4;
    const int fisherYatesRangeSize = fisherYatesRangeMax + 1;
    const double alpha = 0.01;
    const int df = (fisherYatesRangeSize -1) * (fisherYatesRangeSize -1); // degrees of freedom: (size -1)^2
    const decimal criticalValue = 32; // FROM TABLES: Chi-square critical @alpha=0.01 with 16 df (matrix n x n -> 5x5)
    const int trials = 200_000;
    const decimal expected = trials / fisherYatesRangeSize;

    int[,] numOfValOccurencesInPosition = new int[fisherYatesRangeSize, fisherYatesRangeSize]; // numOfValOccurencesInPosition[0,2] = how many times number 2 appeared in position 0

    FisherYatesBag fisherYates = new(fisherYatesRangeMax);
    for (int t = 0; t < trials; t++)
    {
        fisherYates = new(fisherYatesRangeMax);
        int[] permutation = [..fisherYates.GetAllRandomized()];
        for (int i = 0; i < fisherYatesRangeSize; i++) numOfValOccurencesInPosition[i, permutation[i]]++;
    }

    decimal chiSquare = 0;
    for(int i = 0; i < fisherYatesRangeSize; i++) {
        for (int j = 0; j < fisherYatesRangeSize; j++) {
            decimal foundOccurences = numOfValOccurencesInPosition[i, j];
            chiSquare += (foundOccurences - expected) * (foundOccurences - expected);
        }
    }   
    chiSquare /= expected;

    // if chiSquare < criticalValue => Accept H0, otherwise reject H0 (Accept H1)
    Assert.That(chiSquare, Is.LessThan(criticalValue),
        $"With useRest = {useReset}, distribution is likely non-uniform. χ² = {chiSquare} (vs {criticalValue})");
}

A bug was actually found

Thanks to this test I found a bug in my implementation: I was using the Random.Shared.Next method incorrectly.

It turned out that Random.Shared.Next(int minValue, int maxValue) of System operates on the range [minValue, maxValue) instead of [minValue, maxValue].

To fix my implementation it was enough to switch from:
int randomIndex = Random.Shared.Next(0, _remainingCount-1); to
int randomIndex = Random.Shared.Next(0, _remainingCount);

Now the test passes smoothly, like butter.

Conclusion

I don't work in rocket science and I'm not a mathematician either, but a simple Chi-square test from a high school probability class helped me track down a real bug in a real project. It reminded me that even abstract concepts can turn into very practical tools years later. You never really know which formula, proof, or idea will become the missing piece in a future debugging session, so it is worth paying attention even when it feels like "you will never use it in your life".

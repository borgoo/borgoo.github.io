Interfaces vs Abstract classes

[Q.1]:
What are the main differences between interfaces and abstract classes?

[A.1]:

Neither of them can be instantiated, and both are used to define contracts for classes. The key difference is that interfaces act as pure abstractions that enable multiple polymorphism. In fact, a subclass can implement many interfaces but can extend at most one superclass (abstract or not). Abstract classes are more likely to be used to share common code across their subclasses. Personally, I reach for an abstract class over an interface when I have at least one abstract method to implement, some shared code to provide, and I don't want the base class to be instantiable.

PS: starting with .NET 8 even interfaces can implement methods, but I'd ignore that anti-pattern (just mention it to your interviewer 😉).

OOP principles

[Q.2]:
Tell me about the OOP principles you know.

[A.2]:

I remember them through the P.A.I.E. (🤪) acronym:

Polymorphism: a method can change based on the concrete type of the object.
eg.

public abstract class Animal {
    public DateTime BirthDate { get; init;}
    ...
    public abstract void MakeSound();
}
List<Animal> zoo = [new Lion(), new Elephant(), ...]
zoo[0].MakeSound(); // "Roar"
zoo[1].MakeSound(); // "Trumpet"
...

Abstraction: keeps the code structure clean and reusable.

Inheritance: methods and properties can be inherited from a base class by its subclasses.

Encapsulation: resources are accessed or shared only when they need to be.

SOLID principles

[Q.3]:
Now let's get a step further: do you follow some kind of principles to write clean code in OOP?

[A.3]:

I think you're referring to the SOLID principles...
*The interviewer nodded and told me he didn't need the full acronym, but I was ready 😎*

Single responsibility: a class should have only one responsibility. That keeps classes from becoming monoliths and makes the code easier to maintain and test.

Open/Closed principle: aim to extend the code without modifying existing, well-tested logic.
eg.
If I'm handling different payment methods, I avoid giant switch statements. Instead, I define an IPaymentMethod interface and create a dedicated implementation for each new method. It keeps the structure clean and reinforces the first (S) principle.

Liskov substitution principle: a subclass should always be substitutable for its superclass.

Interface segregation principle: don't create monolithic interfaces; break them into smaller ones, each with a clear responsibility. (It's basically the S principle applied to interfaces.)

Dependency inversion: whenever possible, rely on abstractions rather than concrete implementations.

OOAD

[Q.4]:
Are you familiar with OOAD techniques?

[A.4]:

OOAD stands for Object-Oriented Analysis and Design. It's a technique that lets you analyze and design a system from an object-oriented perspective. OOA analysis focuses on:

  • Understanding the problem domain
  • Identifying the objects and their relationships
  • Creating use cases and domain models
OOD, on the other hand, focuses on:
  • Translating the analysis into technical specifications
  • Designing classes and applying design patterns
  • Creating UML diagrams

Design patterns

[Q.5]:
Do you know any design patterns?

[A.5]:

Let me walk you through some of the most common design patterns (my personal big four):

  1. Factory pattern: provides custom creation logic for certain types of objects. In practice I've used it in two main ways:
    • Static factory: a static class with one method that creates specific objects from a configuration input (eg. a switch expression).
    • Factory method: each concrete factory implements a shared interface and exposes a creation method that returns the object instance.
      eg.
      public interface ILoggerFactory // our factory method contract
{
    ILogger CreateLogger();
}

// our concrete factories
public class FileLoggerFactory : ILoggerFactory
{
    public ILogger CreateLogger() => new FileLogger(); // extends ILogger
}

public class ConsoleLoggerFactory : ILoggerFactory
{
    public ILogger CreateLogger() => new ConsoleLogger(); // extends ILogger
}

public static void Main(){
    ILoggerFactory loggerFactory = new FileLoggerFactory();
    ILogger logger = loggerFactory.CreateLogger();
    logger.Log("Debug message");
}
  2. Strategy pattern: encapsulates a family of algorithms and lets you swap them at runtime (choose the strategy dynamically).
    eg.
    public interface IDiscountStrategy
{
    public decimal Apply(decimal amount);
}

public class NoDiscount : IDiscountStrategy
{
    public decimal Apply(decimal amount) => amount;
}
public class SummerSaleDiscount : IDiscountStrategy
{
    public decimal Apply(decimal amount) => amount / 2;
}

public static void Main(){
    ...
    IDiscountStrategy discount = new SummerSaleDiscount();
    Order order = new Order(discount);
    ...
}
  3. Singleton pattern: ensures a class has only one instance and provides a global access point. I've used it for caching, logging, and configuration management.
  4. Observer pattern: defines a one-to-many dependency so that when one object changes state, all dependents are notified and updated automatically. I recently used it to implement a domain event system for my application.

After that I mentioned a few architectural patterns like CQRS, the Repository pattern, and Unit of Work, but I didn't go deep because I wanted to focus on design patterns.

IoC

[Q.6]:
What do you know about IoC?

[A.6]:

IoC stands for Inversion of Control. It's a principle where control of object creation and dependency management is inverted from your code to a framework or container. In .NET, we apply this principle through the Dependency Injection pattern. Instead of classes creating their own dependencies with 'new', dependencies are injected (usually via constructor), and the IoC container manages their creation and lifetime. This provides loose coupling, better testability, and cleaner code - especially in layered architectures where you can organize DI registration per layer using extension methods on IServiceCollection.

Method vs Function

[Q.7]:
What's the difference between a method and a function?

[A.7]:

A function is a standalone piece of code that does not reflect the state of the object it belongs to. A method is a function that is associated with an object and can access (read/write) its state.

Extension methods

[Q.8]:
What is an extension method?

[A.8]:

An extension method lets you add functionality to a class without modifying its source code (literally "extending" it). It must live in a static class and be declared as a static method. The first parameter of the method must be this followed by the type you want to extend, then any additional parameters.
I use them a lot to manipulate IServiceCollection in clean architecture projects by defining each layer's dependency injections directly in that layer. They're also handy when you want to extend base types (string, int, ...) or third-party libraries (HttpClient, etc.). Fun fact: methods like .Select(), .Where(), and .OrderBy() in LINQ are all extension methods.

ORM

[Q.9]:
Let's switch briefly to the database side: what is an ORM? Do you know any?

[A.9]:

ORM stands for Object-Relational Mapping. It's a technique that lets you map objects to database tables and vice versa. I've used Entity Framework (code-first) in several projects to interact with the database. Other popular ORMs I know are Dapper and NHibernate. In my previous job we weren't used to working with an ORM; we interacted with the database through raw SQL queries and stored procedures.

SP vs Function

[Q.10]:
What's the difference between a Stored Procedure and a Function?

[A.10]:

Typically a stored procedure is used to perform a specific action on the database (insert/update/delete/etc.). It guarantees transaction control and can return multiple result sets. A function, on the other hand, is used to calculate something and return it as a single value.

GIT Flow

[Q.11]:
Are you familiar with GIT Flow model?

[A.11]:

Yes, although in my previous job we followed a basic trunk-based development model. In a Git Flow model there are two main branches: main and develop.

  • main: contains production-ready code tagged with a version number
  • develop: contains the latest code under active development
Supporting the process, there are three other branch types:
  • feature/{name}: from develop to develop — used to implement new features
  • hotfix/{name}: from main to main + develop — used to fix critical bugs in production
  • release/{number}: from develop to main + develop — used to prepare a new release

Personally, I don't love this pattern; I prefer a lighter trunk-based approach, but with each commit following the Conventional Commits pattern.

TDD

[Q.12]:
Do you know TDD?

[A.12]:

TDD stands for Test-Driven Development. It's a development process where you start by writing tests and, through continuous refactoring, shape the code until it delivers the desired functionality.

Using .NET to implement SeatingStudents(int[] arr) function

[Q.1]:
Have the function SeatingStudents(arr) read the array of integers stored in arr which will be in the following format: [K, r1, r2, r3, ...] where K represents the number of desks in a classroom, and the rest of the integers in the array will be in sorted order and will represent the desks that are already occupied. All of the desks will be arranged in 2 columns, where desk #1 is at the top left, desk #2 is at the top right, desk #3 is below #1, desk #4 is below #2, etc. Your program should return the number of ways 2 students can be seated next to each other.

[A.1]:

First thing that came to my mind is a visual representation of the desks and the occupied ones:

[][]    /*desks line 0*/
[X][]   /*desks line 1*/
[][X]   /*...*/
...

Second thing is that, in a 2 column layout, two students can be seated next to each other only in 2 ways: A-B;B-A;

Last but not least, a "desk line" could contribute to the total result only if both desks are free.

With all of that in mind, I started implementing a first-approach solution:

public long SeatingStudents(int[] arr)
{
    int k = arr[0];
    BitArray isBusy = new(k, false);
    for (int i = 1; i < arr.Length; i++)
    {
        int index = arr[i]-1;
        isBusy[index] = true;
    }
    long result = 0;
    for (int i = 0; i < isBusy.Length; i += 2) {
        result += !isBusy[i] && !isBusy[i + 1] ? 2 : 0;
    }
    return result;
}

The algorithm is quite straightforward: I'm using a BitArray as a HashSet to store the occupied desks (trying to avoid HashSet overhead) and after that it's just an iteration over all the desk positions (2 by 2) to check if the two desks are free. As you can see, the result leads to:

  • O(n) time complexity -> not that bad!
  • BUT an awful O(k) space complexity due to the BitArray usage. Since no k constraints are provided, this solution is not acceptable (what if K~int.MaxValue ?).

Reading the question requirements again, I realized that I already have the information about the busy desks in the input array and that array is even already sorted!

So I came up with a new approach: use a pointer to iterate over the "desk lines" and another pointer to consider the helpful "busy desk" information (stored in input array).

Knowing that, the tricky part became the correct update of the second pointer (currBusyDeskIndex). With some adjustments I came up with this solution:

public long SeatingStudents(int[] arr)
{
    if (arr.Length < 1) throw new ArgumentException("Invalid input.");

    int k = arr[0];
    if (k % 2 != 0) throw new ArgumentException("Invalid input.");

    int currLineOfDesks = 0;
    int currBusyDeskIndex = 1;
    long result = 0;
    int numOfDesksLines = k / 2;
    while (currLineOfDesks < numOfDesksLines) {

        bool thereAreSomeBusyDesksDataRemaining = currBusyDeskIndex < arr.Length;
        if (!thereAreSomeBusyDesksDataRemaining) {
            int remainigLineOfDesks = numOfDesksLines - currLineOfDesks;
            result += 2*remainigLineOfDesks;
            break;
        }
        int currBusyDeskValue = arr[currBusyDeskIndex] -1;
        bool isLeftColumn = currBusyDeskValue % 2 == 0;
        int currBusyDeskLine =  isLeftColumn ? currBusyDeskValue / 2 : (currBusyDeskValue - 1 )/ 2;

        bool currLineIsBusy = currBusyDeskLine == currLineOfDesks;
        if (currLineIsBusy) {
            
            currBusyDeskIndex++;
            if (isLeftColumn && currBusyDeskIndex < arr.Length) {

                int newBusyDeskValue = arr[currBusyDeskIndex] - 1;
                bool isANewLeftColumn = newBusyDeskValue % 2 == 0;
                if (isANewLeftColumn)
                {
                    currLineOfDesks++;
                    continue;
                }

                int newBusyLine = (newBusyDeskValue - 1) / 2;
                bool stillReferToCurrentLine = newBusyLine == currLineOfDesks;
                if (!stillReferToCurrentLine) {
                    currLineOfDesks++;
                    continue;
                }   
                currBusyDeskIndex++;
            }

            currLineOfDesks++;
            continue;
        }
        result += 2;
        currLineOfDesks++;
    }

    return result;
}

Now I'm satisfied. I've obtained:

  • O(n) time complexity -> still not that bad!
  • O(1) space complexity -> perfect!

Bulk SQL insert from CSV file

[Q.1]:
You have a CSV file with a list of very large data sets to be inserted into SQL tables. You are not certain that each column has the correct (or properly formatted) data type. How would you handle this bulk insert?

[A.1]:

I'd follow the classic staging pipeline: stage first, validate second, load last.

  1. Create a staging table with every column typed as NVARCHAR
  2. Load the CSV data into the staging table
  3. Validate each column with the matching TRY_CAST
    eg.
    SELECT * FROM StagingData WHERE TRY_CAST(Col2 AS INT) IS NULL AND Col2 IS NOT NULL;
  4. Fix any invalid rows directly in staging
  5. Insert the cleaned rows into the final table

Alternatively, you can build an ETL (.NET) pipeline:

  1. Read the CSV file
  2. Split each line with LINQ and validate/normalize the values
  3. Write the resulting objects to the destination table

Clustered index

[Q.2]:
What is a clustered index?

[A.2]:

It's an index that defines how a table's rows are physically ordered on disk. There's only one clustered index per table, and by default the primary key becomes the clustered index.

Unsafe struct

[Q.3]:
Look at this code: 

unsafe struct MyStruct {
    public int MyField;
    public int* MyPtr;
}
What can you tell me? Is this considerable unmanaged code?

[A.3]:

The unsafe keyword is required because the struct contains a pointer (a C-style pointer); it allows direct memory manipulation. Unsafe structs are NOT unmanaged—they still run under the CLR (GC, JIT, exception handling...), they just bypass some type and bounds checks (eg. you can reference a corrupted address or read the wrong type). Unmanaged code is code that the CLR doesn't control (eg. native C DLLs).
Sometimes unsafe code is handy for very fast, low-level byte serialization when you need to read/write memory directly.
eg.

unsafe {
    MyStruct s = new MyStruct { X = 10, Y = 20 };
    byte* ptr = (byte*)&s; // pointer to the struct in memory
    byte[] bytes = new byte[sizeof(MyStruct)];
    for (int i = 0; i < sizeof(MyStruct); i++) bytes[i] = ptr[i];
}

Using .NET implement the FilterDuplicates(int[] arr) function [time limit: 10']

[Q.5]:
Using .NET implement the FilterDuplicates(int[] arr) function that returns a new array with duplicates removed while maintaining the original order of the elements.

[A.5]:

Just keep track of the elements already seen and add to the result array only the ones that aren't there yet: 

public int[] FilterDuplicates(int[] arr) {
    HashSet<int> seen = [];
    List<int> result = [];
    foreach(int v in arr) {
        if (!seen.Contains(v)) {
            seen.Add(v);
            result.Add(v);
        }
    }
    return result.ToArray();
}

Using .NET implement the CountHappyDogs(int n, int availableSteaks) function [time limit: 20']

[Q.6]:
Using .NET implement the CountHappyDogs(int n, int availableSteaks) function that maximizes the number of happy dogs.
Constraints:

  • A dog is happy if it has exactly 8 steaks
  • A dog die if it has exactly 4 steaks
  • Each dog MUST have at least 1 steak
  • Each dog can eat at most 8 steaks
  • You MUST give to the dogs all the possible steaks (BUT a dog cannot eat more than 8 steaks)

[A.6]:

It's a classic coin-style problem: greedily assign 1 steak to each dog, then loop from the start giving each dog the extra steaks needed to hit the happy state (8 steaks). Just remember to check whether the last dog ends up in the deadly state (4 steaks). If that happens, borrow one steak from the previous dog (so subtract 1 from the result). 

public int CountHappyDogs(int n, int availableSteaks) 
{
    const int toBeHappy = 8;
    const int toBePoisoned = 4;
    const int minSteaks = 1;
    const int toBeAdded = toBeHappy - minSteaks;

    int oneSteakForEachDog = n;
    availableSteaks -= oneSteakForEachDog;

    if (availableSteaks < 0) return 0;

    int result = availableSteaks / toBeAdded;

    if (result >= n) return Math.Min(result, n);

    int lastDogSteaks = 1 + (availableSteaks  % toBeAdded);

    if (lastDogSteaks == toBePoisoned) return result - 1;

    return result;
}

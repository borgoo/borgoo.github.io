BlackJack AI - Part 0

My journey to create a BlackJack AI

December 19, 2025 (today) @boborgo

AI is everywhere nowadays, and I'm falling behind.

Since model and reinforcement learning are the buzzwords that come to my ears most often, I decided to start a project that involves both of them.

Because I'm a little bit ashamed of myself and my knowledge in this area, I will apply the law of retaliation and share my entire journey with you.

My current knowledge

I'm starting this adventure with only these two concepts in my mind:

  • A model is "something" (a mathematical function) that can be trained (its parameters can be tuned) to "learn" how to do something (return a desired output given an input).
  • Reinforcement learning is a technique based on rewards: the agent is rewarded for good actions and punished for bad actions.

At this moment, it's not clear to me how the agent will be able to know that its job is to maximize the rewards from its actions.

Thinking

Given what I know so far, it seems clear that I need to create a task for the model that I know well, one that is easy to code and can be iterated on millions of times. Verifying the quality of the model's output given a specific input should also be an important factor.

Finally, I would like to have fun advancing in this project. I'm already dreaming of having a nice UI to play with the model eventually, or at least to see the simulations in action... so is there something that I like... with clear rules and a clear goal?... maybe something.. like..

BLACKJACK!

Yeah, Blackjack should do!

Now that I have my task, I can proceed with my favorite part: coding the game logic. A blackjack table where the model can play against the dealer.

Some considerations before starting:

  • The game consists of N decks of cards dealt by the dealer to the player one card at a time.
  • The dealer should cut the deck at a certain point from the end (by rules) — for simplicity, this value will be fixed for now.
  • The model should be able to hit, stand, split, or double down its hand.
  • It should be heavily punished for losing all the bankroll (when a refill is needed).
  • Rewards should be 1.5 times higher for winning by Blackjack.
  • The model needs to manage the bankroll, count cards, and evaluate deck penetration.
  • No side bets or insurance for now.

Mmh, some other considerations...

  • Should the model be able to play against the dealer multiple times when the bankroll runs out?
  • No fancy clean architecture for now... a simple console application will do.

Enough talking... let's get dirty...

Part 0.1

Running down the rabbit hole (studying how to architect the game logic to be as AI-friendly as possible), I found that my approach based on raw state would take too much effort for an MVP (Deep Learning involved, as I understood it).

A better first approach would be to work with engineered features that require much less reinforcement learning complexity to train the model.

It's like focusing on the Basic Strategy without deviations and bankroll management for a rookie player!

That allows me to easily identify the features that are important to the model:

public readonly record struct EngineeredFeatures(
    int DealerFaceUpCard,
    int PlayerHardTotal,
    bool PlayerHasSoftAce,
    bool PlayerHasPair
);

I'm getting excited already 😁 Let's see if I can make it work...
